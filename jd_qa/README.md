# jd_qa — 测开 / QA 岗位 JD 备战

集中存放**测试开发 / QA** 岗位的 JD(职位描述),并把每一条 JD 拆解成可与仓库已有内容联动的**可执行备战清单**。

## 命名规范

文件名格式:`{公司}_{岗位简称}_{YYYYMMDD}.md`

| 公司 | 岗位 | 投递日期 | 文件名示例 |
| --- | --- | --- | --- |
| 腾讯 | 测开 | 2026-07-30 | `腾讯_测开_20260730.md` |
| 字节 | 测开 | 2026-08-01 | `字节_测开_20260801.md` |
| 网易 | QA | 2026-08-05 | `网易_QA_20260805.md` |

- 日期用**投递/接触该岗位的日期**(首次看到或首次投递日),便于排序。
- 同一家公司多个岗位 / 多次投递:各自独立成文件,日期区分。
- 岗位简称尽量统一:`测开` / `QA` / `测试` / `SDET` 等,保持个人习惯一致即可。

## 用法

1. 复制 `_TEMPLATE.md`,按命名规范改名。
2. 填写「基础信息」和「JD 原文」。
3. 在「重点技能拆解」里逐条标注掌握程度,并指向仓库内对应笔记 / 题解。
4. 把弱项整理进「备战 checklist」。
5. 每投递一轮、面完一轮,回到文件顶部更新「状态」,并在「面试记录区」补充心得。

## 状态约定

文件顶部「状态」字段使用以下取值,代表 JD 的生命周期:

`待投递` → `已投递` → `笔试` → `一面` → `二面` → `三面` → `HR面` → `Offer` / `已挂`

(不经历某轮就跳过;终态只保留 `Offer` 或 `已挂`。)

## 与仓库其他模块联动

JD 不是孤立的,要和已有的学习/刷题成果对接:

- **技能拆解对照学习计划**:`../learning/python/Python学习计划.md` 是总纲,`01_basics.py` ~ `04_master.py` 是分阶段笔记,`python_basics_advanced_exam.py` / `python_interview_exam.py` 是自测卷(运行即出分)。JD 里的 Python 要求可直接对照标强弱。
- **关联真实面试题**:`../interview/` 已有真题可交叉引用,例如:
  - `../interview/腾讯测开1面.cpp` ~ `腾讯测开3面.cpp`(腾讯测开 3 轮)
  - `../interview/网易1.cpp` ~ `网易3.cpp`(网易笔试)
  - `../interview/deepseek1.py`、`deepseek2.py`(DeepSeek 面试)
- **弱项题型回到刷题库**:`../cpp/` 是 LeetCode 风格的 C++ 题解(链表 / 数组 / 字符串 / 树 / DFS·BFS 等),JD 拆出的薄弱算法可直接链接到对应题解。
