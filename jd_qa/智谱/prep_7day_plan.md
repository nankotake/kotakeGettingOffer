# 智谱测开 · 技术面 7 天备战计划

> **背景**:HR 面已过,后续 2 次技术面。岗位招 2 人(一前端一后端),**本人定位:后端方向**。备战窗口:约 1 周。
> **核心策略**:1 周补不齐 4 块强项,必须分级。后端方向 + JD 硬性要求 + 测开面试规律三者取交集,定出主攻和取舍。

---

## 0. 优先级分级(先认这个,再排计划)

| 级别 | 内容 | 每天投入 | 理由 |
| --- | --- | --- | --- |
| **S 必攻克** | ① 项目深挖 ② AI Agent 深度 ③ 实时通信链路 | ~60% | 项目是你的卖点;AI Agent 是岗位命门;实时通信是 JD 硬性且后端通用 |
| **A 够用即可** | 客户端自动化(Electron/Web/CDP) | ~25% | 你是后端方向,面试官对客户端预期远低于前端候选人,聊懂原理即可,别深钻 |
| **B 保持手感** | 算法 + 系统设计 | ~15% | 有 `cpp/` 基础,每日少量维持;测开技术面算法权重低于纯开发岗 |

**取舍纪律**:S 级没吃透,绝不投入 A 级深处。宁可客户端「聊懂答得出」,不要四块都半生不熟。

## 1. 七天作战表

> 每天 = 主线块(S)+ 补强块(A)+ 手感块(B)+ 复盘。每块给到具体动作和产出物,做完打勾。

### Day 1 — 项目深挖(地基,最重要的一天)
**目标**:把简历里 3 个 AI/核心项目挖到能扛 3 轮追问(为什么这么设计/不用 X 方案?瓶颈?复盘?)。

- [ ] **「AI 提效工具开发」拆成 STAR + 三层追问**
  - S/T:业务痛点是什么?为什么人工做不行?
  - A:managed agent 怎么编排的?调了哪些工具?上下文怎么管?为什么用 agent 不用普通脚本?
  - R:覆盖率/效率提升数据?线上有无误判?怎么治?
  - 预演追问:① 上下文超长怎么处理 ② 工具调用失败如何重试/降级 ③ 为何选 managed agent 而非单次调用
- [ ] **「酒店场景 AI 评测」拆 STAR**
  - LLM-as-judge 的 prompt 怎么设计?怎么保证 judge 本身可信(评判者偏差)?
  - 严谨性/安全性/一致性指标具体怎么算?90% 准确率的分母分子是什么?
  - 发现的 4 类问题(绝对化表述、亲子识别、时间段、字数)→ 每类给一个真实 case
- [ ] **「风控处置闭环」拆 STAR**(0-1 体系建设的佐证)
  - 完整链路(发现/豁免/通知/处罚/申诉/审核)你负责哪段?
  - 线上问题 10→2 的归因:是测试手段拦的?还是系统改造?你具体做了什么?
- [ ] 产出:`projects_deepdive.md`(见本目录,把以上填进去)

### Day 2 — AI Agent 深度 + 流式(岗位命门)
**目标**:从「用过」升级到「讲得清原理」,能应对智谱最核心的追问。

- [ ] **Agent 架构原理**(能白板讲)
  - ReAct / Plan-Execute / managed agent 三种范式区别与适用场景
  - 任务编排(planning)、工具调用(tool use)、上下文管理(context window)
  - function calling 机制:LLM 如何决定调用哪个工具、参数如何结构化
- [ ] **流式 token 输出测试**(JD 反复强调)
  - SSE 增量校验、首 token 时延(TTFT)、整体吞吐、中断恢复
  - 写一段伪代码/思路:如何断言一个流式响应「完整且有序」
  - 思考点:思考过程(thinking)、工具调用追踪、diff/补丁、权限请求各自怎么测
- [ ] **LLM 质量保障通识**(对位你 AI 评测经验)
  - 评测集构建、幻觉/越狱、流式对话范式 QA、回归基准
  - 准备一段:我的 AI 评测经验如何迁移到 Coding Agent 测试
- [ ] 产出:`study_notes_agent.md` 关键问答卡片

### Day 3 — 实时通信链路(后端硬实力 + JD 硬性)
**目标**:SSE/WebSocket/WebRTC 能讲清协议差异和测试要点,有可讲的小实操。

- [ ] **协议对比**(必背一张表):SSE vs WebSocket vs HTTP/2 vs WebRTC
  - 单向/双向、基于什么、保活机制、典型场景
- [ ] **SSE 深挖**(智谱流式核心)
  - 报文格式(`text/event-stream`、`data:`、`id:`、`retry:`)、自动重连、断点续传
  - 测试点:增量有序、连接中断后 last-event-id 续传、服务端心跳
- [ ] **WebSocket 深挖**
  - 握手(HTTP Upgrade)、帧格式、心跳 ping/pong、断线重连策略
  - 测试点:弱网/抖动下的重连、状态一致性、长连接保活超时
- [ ] **WebRTC 基础**(远程控制用,理解即可)
  - 信令、ICE/STUN/TURN、P2P 媒体链路;测试只需讲清难点
- [ ] **小实操(强烈建议)**:抓一次 ZCode/Claude Code 的流式响应(浏览器 F12 → Network → EventStream),截图存证,面试可讲"我抓过真实 Coding Agent 的流式帧"
- [ ] 产出:`study_notes_realtime.md`

### Day 4 — 客户端自动化(够用即可,A 级)
**目标**:后端方向不深钻,但 Electron/Web/CDP 能讲清原理和一个最小实践。

- [ ] **Electron 架构**(必懂)
  - 主进程 vs 渲染进程、IPC 通信、为何测它比测普通 Web 难
  - Playwright Electron 怎么连主进程(`_electron.launch`)、怎么 mock 文件/对话框
- [ ] **Web 自动化**(Playwright 优先,TestNG 经验可类比)
  - 选取器、auto-waiting、trace viewer(对位你「根因定位」能力)
  - 移动端 Web:响应式 + UA 模拟 + 触摸事件差异
- [ ] **CDP 根因定位**(JD 第 8 条硬性,重点)
  - Chrome DevTools Protocol 能做什么:Network、Console、Runtime、Performance
  - 准备一个故事:你在美团靠中间件链路定位根因(线上问题 10→2),迁移到客户端用 CDP 同样思路
- [ ] **远程 workspace 链路**(加分项,理解概念)
  - SSH/WSL/Docker 作为 Coding Agent 的执行环境,测试点:连接稳定性、文件同步、权限
- [ ] 产出:`study_notes_client.md`

### Day 5 — 测开八股 + 接口/契约/mock(后端基本盘)
**目标**:把后端测开的高频考点过一遍,确保基本盘不丢分。

- [ ] **测试理论**:测试用例设计方法(等价类/边界值/场景法/正交)、缺陷生命周期、回归策略
- [ ] **接口测试**:Postman/httpx、契约测试(Consumer-Driven Contract)、mock 与流量录放(对位 JD 第 6 条)
- [ ] **中间件链路**(你的强项,准备好讲):Kafka 消息丢失/重复/顺序、Redis 缓存三大问题、MySQL 事务/索引
- [ ] **CI/CD + 质量**:Jenkins 流程、自动化有效性/稳定性治理(对位你「自动化合规检查」经验)
- [ ] **数据库 & Linux**:SQL 题、常用排查命令(top/strace/netstat/grep 日志)
- [ ] 产出:`study_notes_qa_basics.md`

### Day 6 — 系统设计 + 模拟面试
**目标**:测开系统设计题能搭框架;全流程模拟一次,暴露盲点。

- [ ] **系统设计模板**(测开视角)
  - 题型预测:① 设计一个 AI 测试 Agent 的架构 ② 设计 Coding Agent 流式输出的测试方案 ③ 设计接口自动化平台
  - 通用框架:理清需求→拆模块→定数据流→定测试点→定监控告警→权衡取舍
  - 重点预演:「设计一个能自主探查界面、复现路径、分析流式问题的测试 Agent」(= JD 岗位本身)
- [ ] **模拟面试**(自己录音或找人对练)
  - 自我介绍 3 分钟版(见 JD 文件「面试核心叙事」)
  - 项目深挖 15 分钟 + 八股 15 分钟 + 反问 5 分钟
  - 录音回放,记录卡壳点补到笔记
- [ ] 更新所有 study_notes,合并高频问题清单 `mock_questions.md`

### Day 7 — 总复盘 + 心态 + 反问准备
**目标**:查漏补缺,把所有产出物压缩成「考前 1 小时速览」。

- [ ] 过一遍 Day 1-6 所有未打勾项,补齐或主动放弃(放弃要明确面试话术)
- [ ] 整理「考前 1 小时速览」(打印/手机):项目 STAR 卡片 + Agent 三范式 + 协议对比表 + 八股高频 20 问
- [ ] **反问准备**(面试官是后端/质量方向,体现深度):
  - 「团队目前 AI 测试 Agent 落地到什么阶段?最大的质量瓶颈在哪一端?」
  - 「后端方向的候选人,团队期望在客户端多端上达到什么程度?」(趁机确认你的方向定位和预期)
  - 「流式/实时链路现在主要靠手工还是已有自动化?我进来能推进哪块?」
- [ ] 休息,保证睡眠

## 2. 两次技术面的预期差异 & 应对

> 招 2 人一前端一后端,两次技术面大概率是「**深度面 + 广度面**」组合,而非「前端面 + 后端面」分割(你被定位后端,不会考你前端深水区)。但要防两种排列:

### 可能的面 1:项目 & 深度面(后端面官)
- **重心**:你简历的 AI Agent / AI 评测 / 风控项目,会往深里挖(为什么这么设计、瓶颈、复盘)
- **考点**:Agent 原理、服务端中间件链路、接口/契约/mock、流式测试
- **你的策略**:主动把话题引向你最强项(AI Agent 实操),每个项目用 STAR 讲透,主动给数据和复盘
- **防御点**:客户端问题坦诚「后端方向,正在补,已有 Playwright+CDP 学习实践」,不硬撑

### 可能的面 2:广度 & 系统设计面(架构/负责人面官)
- **重心**:技术广度 + 一个开放系统设计题 + 软素质
- **考点**:测开八股广度、SSE/WebSocket 原理、一个设计题(很可能是「设计 AI 测试 Agent」或「设计流式测试方案」)、质量体系建设思路
- **你的策略**:广度题快答不拖;设计题用通用框架结构化输出;主动结合美团 0-1 经验(告警系统/数据测试模板/风控闭环)讲体系化能力
- **加分动作**:设计题里主动提「这块我会用 Agent 编排来做,类似我在美团做的 managed agent」,把项目自然嵌入答案

### 关键纪律(两场面通用)
- **不会就说「这块我了解不深,但我的理解是 X,不确定对不对」** —— 比硬编强百倍,智谱这种技术深度公司最反感不懂装懂
- **每个答案尽量落回你的真实项目** —— "我在美团做 AI 评测时..." 是你最可信的弹药
- **客户端短板统一口径**:后端方向 + Agent 能力可迁移 + 已有具体学习实践(可挂 GitHub),不要试图假装很熟

## 4. 每日节奏建议(可调)

```
上午(精力好): S 级主线块   → 项目深挖 / Agent / 实时链路
下午:          A 级补强块   → 客户端 / 八股
```
